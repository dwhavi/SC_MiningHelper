# SC_PadControl

Star Citizen용 PC 광물 오버레이 + 태블릿 입력 덱. 설치 프로그램 없이 Windows용 `SC_PadControl.exe` 하나로 실행합니다. 태블릿은 선택 사항이며, 광물 결과는 PC 게임 화면에만 표시합니다.

## 빠른 시작

1. [Releases](../../releases)에서 최신 `SC_PadControl.exe`를 받습니다. 이전 exe를 종료한 뒤 새 exe로 교체하세요. 출처를 확인한 파일만 실행하세요.
2. exe를 쓰기 가능한 폴더에 두고 더블클릭합니다. Python 설치나 콘솔 창이 필요하지 않습니다.
3. 게임을 보더리스 모드로 실행합니다. 제어 창의 **화면 영역 지정**으로 RS 숫자와 근접 스캔 패널을 각각 드래그합니다. 해상도/HUD가 바뀌면 다시 지정하세요.
4. 태블릿은 같은 Wi-Fi에서 제어 창 **최상단 연결 카드**에 표시된 `http://PC_IP:8377` 주소에 접속하고 6자리 페어링 코드를 입력합니다. **주소 복사** 버튼으로 URL을 복사할 수 있고 페어링 코드도 바로 아래 표시됩니다. 이 카드는 설정을 스크롤해도 보입니다. Windows 방화벽은 신뢰하는 개인 네트워크에만 허용하세요.
5. PC 제어 창의 **키바인드 XML 선택**에서 현재 쓰는 프로필을 고르고 태블릿 페이지를 새로고침하세요. XML에서 확인되지 않은 버튼은 **키 지정 필요**로 잠깁니다. 패드 상단 **키 설정**에서 실제 게임 키를 직접 지정할 수도 있습니다. ESC만 고정 키입니다. 게임에서 각 버튼의 동작을 확인한 뒤 사용하세요.

## v0.44: 휠 통합 디자인 / v0.42 물리 수식자 입력

오른쪽 Alt/Ctrl 등 좌우 수식자는 Windows IME/언어에 따라 다시 변환하지 않고 물리 스캔코드로 보냅니다. 오른쪽 Alt는 `E0 38`에 해당하는 확장키로 눌림/해제를 모두 전송합니다. 일반 키 변환이 실패하면 잘못된 0 스캔을 보내지 않고 오류를 표시합니다. 이전 입력 지연은 유지합니다. 실제 게임에서의 개선 여부는 확인이 필요합니다.

입력 진단은 exe 옆 `input_diagnostics.jsonl`에 이 앱이 전송한 VK/스캔/플래그/전송 결과/오류만 기록합니다. 실제 키보드를 감시하거나 게임 메모리를 읽지 않습니다. 약 256KB에서 1개 이전 로그로 교체합니다. 입력 API 성공은 Windows 전송 성공이며 게임 동작 성공이 아닙니다. 실행 권한 차이로 차단되면 별도 확인이 필요합니다.

v0.44에서는 휠과 같은 재질·공통 림·베벨을 사용한 동심원 외곽 호로 전원 버튼을 통합했습니다. v0.43에서는 스케치에 맞춰 원형 UI 바깥 상단~중앙 높이의 왼쪽 곡선 패널에 **함선 전원**, 오른쪽 곡선 패널에 **엔진 전원**을 배치했습니다. 아래 전원 버튼 쌍은 제거했고 6웨지는 유지합니다. 각각 XML의 `spaceship_power.v_power_toggle`, `spaceship_power.v_power_toggle_thrusters`를 사용하며 미확인/중복이면 잠깁니다. 켜기 전용이 아니라 **전환**이므로 이미 켜져 있으면 꺼집니다. 이 두 바로가기는 XML 전용이며 기존 전력·시스템 페이지는 유지합니다.

## v0.41: 시퀀스 단계 키 직접 변경

패드 상단 **키 설정 → 조종·착륙 → LAUNCH / LANDING**에서 단계마다 키와 수식자를 선택하고 **시퀀스 설정 저장**을 누릅니다. XML 사용을 선택하거나 **이 단계 XML로**를 누른 뒤 저장하면 해당 단계만 XML로 돌아갑니다. **전체 기본값**은 모든 단계 키와 간격을 기본으로 돌립니다. 게임의 키 설정을 바꾸는 기능은 아니므로 실제 게임 키와 맞춰 주세요.

사용자 키는 PC 별도 설정 파일에 저장되고 XML/기존 덱은 바꾸지 않습니다. 일반 이동키·시스템 단축키·서로 다른 액션의 중복 키는 거부합니다. Space 단독만 LAUNCH의 함선 띄우기에서 허용하며, 이 단계는 지정 키를 1.5초 유지합니다. 키가 비어 있는 다른 단계가 있어도 일부 단계부터 저장할 수 있지만 전체가 확인될 때까지 실행은 잠깁니다. v0.40의 설정 목록 터치 스크롤 수정도 포함합니다.

## v0.39: 원형 휠 + 시간 간격 시퀀스

조종·착륙 페이지는 중앙 비행 준비와 6개 버튼(LAUNCH, 나이트 비전, 랜딩기어, LANDING, VTOL, 함선 전등)으로 구성됩니다. 일반 키는 청록, 시퀀스는 주황 네온과 채움 효과로 구분합니다. 색상은 입력 피드백이며 게임 상태가 아닙니다.

- LAUNCH: 격납고 요청 → 2000ms 대기 → Space 1500ms 유지(함선 띄우기) → 1000ms 대기 → 랜딩기어 토글. Space는 이 단계에서만 허용한 이동키 예외입니다.
- LANDING: 도킹 요청 → 1500ms 대기 → 랜딩기어 토글. 착륙 허가/격납고 열림을 확인하거나 자동으로 착륙시키지는 않습니다.
- 실제 키는 선택한 XML이 기본입니다. v0.41부터 키 설정에서 각 단계의 키/수식자와 대기 시간(200~10000ms)을 직접 바꿀 수 있습니다. XML에 없는 단계도 직접 지정 가능합니다. 하나라도 미지정/충돌이면 시퀀스 전체가 잠깁니다. 단계 추가와 반복은 지원하지 않습니다.
- 한 번에 하나만 실행, 실행 중 다른 입력/홀드 시작 차단, 포커스 재확인, 취소 버튼 하단 고정. 취소/포커스 이탈은 유지 중인 Space도 놓습니다. 새로고침/다른 패드에서도 진행 중 상태를 다시 표시합니다.
- **게임 완료 피드백이 없습니다.** 문이 열리지 않았거나 기어 상태가 반대여도 정해진 시간에 다음 키가 갑니다. 처음에는 넓고 안전한 곳에서 간격을 조정하고 상태를 직접 확인하세요. 기본 2초가 격납고 개방을 보장하지 않습니다. 기어는 상태 지정이 아닌 토글입니다.
- **자동 순차 입력은 매크로/자동화 영역이며 이용약관·안티치트 안전을 보장하지 않습니다.** 실제 게임에서 검증하지 않았습니다.

기존 `deck_layout.json` v4를 직접 두었다면 그 파일이 계속 우선합니다. 새 기본 휠을 보려면 원본을 백업해 이름을 바꾸고 재시작하세요. 프로그램은 기존 덱과 게임 XML을 덮어쓰지 않습니다.

## PC 광물 오버레이

- 투명/클릭 통과 오버레이, 가운데 정렬, 하단 광물 간략 정보
- RS 기반 광물 후보와 암석 개수, 통상 난이도 미리보기
- 근접 스캔 패널 OCR로 광물 구성비/저항/불안정도/질량 읽기
- Prospector + Helix I + Rieger-C3 + Focus III 기준 채굴 판정 **BETA**
- 제어 창에서 스캔/오버레이 on/off, 투명도, 위치, 캡처 영역 변경
- 화면 읽기만 사용하며 게임 메모리 읽기/인젝션/게임 후킹을 하지 않습니다.

RS만으로 실제 구성비나 암석의 저항/질량을 알 수는 없습니다. OCR과 판정 임계값은 인게임 보정이 필요하며 보장값이 아닙니다. `config.json`의 `verdict_thresholds`에서 조정할 수 있습니다.

### 단축키 변경 주의

게임의 F8(출력 초기화), F11 등과 충돌하지 않도록 보조 프로그램 단축키에 **Ctrl+Alt**를 붙였습니다.

| 단축키 | 기능 |
|---|---|
| Ctrl+Alt+F8 | 오버레이 표시/숨기기 |
| Ctrl+Alt+F9 | 위치 조정 모드, 다시 누르면 저장 |
| Ctrl+Alt+F10 | 화면 읽기 영역 지정 |
| Ctrl+Alt+F11 | 현재 읽기 영역 표시 |

제어 창 버튼으로도 같은 동작을 할 수 있습니다.

## 태블릿 덱 v4

- **최상단 고정 전력 배분**: 무기·엔진·실드 출력 각각 +/−와 초기화. 네 페이지 어디서든, 스크롤 중에도 보입니다. 실제 핍 수치는 읽지 않습니다. XML 확인 또는 사용자가 직접 지정한 키만 활성화합니다.
- 공통 바로가기: **착륙 요청 / 스타맵 / 모비글라스 / ESC**. 네 페이지에 계속 표시됩니다.
- **채굴** 12개: 채굴·스캔·비행 모드 직접 선택, 핑, 레이저, 파쇄/추출, 출력 ±, 모듈 1~3, 전등
- **조종·착륙** 10개: 비행 준비, 기어, VTOL, 전등, SCM/NAV 직접 선택, 도킹 요청·카메라, 3인칭, 자유 시점
- **전력·시스템** 5개: 전체·엔진·무기·실드 전원 전환, 문 잠금 전환. 출력 배분 7개는 최상단으로 이동했습니다. 전원 전환은 주황색 별도 구역이며 시스템이 꺼질 수 있습니다.
- **일반·출입** 8개: 상호작용, 인벤토리, 커서, 채팅, 문 열기·닫기, 좌석 나가기, 손전등
- **인벤토리는 함선에서 엔진 키와 혼동할 수 있어 잠금 상태**, **좌석 나가기는 올바른 액션 확인 전 잠금 상태**입니다. `v_emergency_exit`나 사출 액션을 좌석 나가기라고 추측하지 않습니다.
- WASD 등 일반 이동·속도 조작, 임의 매크로, 자동 반복, 자폭·사출·카고 투하, 전투·살베지 기본 버튼 없음
- `B` 홀드로 마스터 모드와 퀀텀 실행을 섞지 않습니다. SCM/NAV 직접 선택만 두며 **퀀텀 실행은 현재 패치 액션 검증 전 추가하지 않았습니다.**
- 1버튼 = 1키 또는 조합키. 출력 ±는 1회씩 전송하며 홀드는 직접 누르는 동안만 유지합니다.
- 탭은 수식자를 잠깐 안정시킨 뒤 본키를 약 0.1초 유지합니다. 게임이 짧은 합성 입력(특히 오른쪽 Alt 조합)을 놓치지 않도록 하는 시간이며, 반복 전송은 아닙니다.
- 색상은 페이지 선택·손가락 누름·주의 구역 표시일 뿐, 게임의 전원/모드 상태가 아닙니다.
- 태블릿은 4열, 폰은 오터치 방지를 위해 2열이며 작은 화면은 스크롤합니다. 최상단 출력 배분은 무기·엔진·실드 순서로 +/−를 세로로 맞춰 놓습니다.
- 결과는 태블릿으로 보내지 않습니다. 테스트 버튼은 PC 오버레이 확인용입니다.

### 패드의 키 설정 팝업

상단 **키 설정**을 열면 전력 배분 / 공통 / 각 페이지의 버튼을 선택할 수 있습니다. **키 지정 필요한 버튼만** 필터로 미지정 버튼을 모아 보세요.

1. 버튼 선택 → 보낼 키 선택 → 필요하면 좌/우 Ctrl·Alt·Shift 체크 → **이 키로 저장**
2. 사용자 지정은 XML보다 우선합니다. 버튼에 **사용자**로 표시되며, PC의 `deck_key_overrides.json`에 저장되어 재시작 후에도 유지됩니다. 기존 `deck_layout.json`과 게임 XML은 수정하지 않습니다.
3. **XML로 되돌리기**는 해당 사용자 지정을 삭제합니다. XML에 바인딩이 없다면 다시 잠깁니다.

페어링된 패드만 설정을 읽고 저장할 수 있습니다. 설정은 PC 전체에 적용되므로 다른 패드도 새로고침하면 같은 값을 봅니다. 이 기능은 **게임 자체의 키 설정을 바꾸지 않습니다.** 게임에서 현재 프로필과 실제 동작을 확인하세요.

단일 키 또는 수식자+단일 키만 지원합니다. 이동 키(조합 포함), Windows 키, 수식자만 누르기, 여러 키 순서/매크로, 중복 키는 거부합니다. 휠은 탭만 가능합니다. 서버가 현재 XML·다른 덱 버튼과의 중복도 확인하지만 XML에 빠진 게임 기본키까지 감지할 수는 없습니다. 인벤토리·좌석 나가기 등 기존 안전 잠금 버튼과 ESC 고정 키는 여기서 변경할 수 없습니다.

### 키바인드 XML: 미지정이면 전송하지 않음

PC의 **키바인드 XML 선택**에서 현재 프로필의 `actionmaps.xml` 또는 인게임에서 내보낸 XML을 선택합니다. LIVE/PTU나 오래된 내보내기 파일을 임의 선택하지 않습니다. 게임 파일을 수정하거나 업로드하지 않습니다.

- 사용자 지정이 없다면 액션의 지원되는 키보드/마우스 `rebind`가 XML에 있어야 버튼이 활성화됩니다. 유일한 예외는 이름 그대로 `ESC`를 보내는 공통 고정 키입니다.
- 사용자 지정이 없고 XML도 없거나 깨졌거나 바인딩이 누락되면 **키 지정 필요**입니다. 부분 내보내기·조이스틱 전용·지원하지 않는 축·명시적 키 해제에서도 기본 키를 추측하지 않습니다.
- XML에서 같은 키가 여러 액션에 지정되면 해당 버튼을 잠그며, 이동용 단독 키와 휠 홀드도 차단합니다. XML에 없는 게임 기본 키까지 충돌을 감지하는 기능은 아니므로 게임에서 직접 확인해야 합니다.
- XML의 액션 이름은 커뮤니티 자료를 참고한 식별자입니다. 현재 패치에서 달라졌다면 잠금 상태가 유지될 수 있습니다. XML 연결만으로 현재 게임의 활성 프로필이나 실제 동작이 검증되지는 않습니다.
- 파일 변경 시간으로 다시 읽습니다. 표시는 태블릿 새로고침 때 반영됩니다. 입력 요청 때도 서버가 현재 XML/사용자 지정과 허용 동작을 검사하므로 화면에 남은 예전 키로 새 입력을 보낼 수 없습니다.
- 참고작 `nodieCode/tablet-deck`의 키 프로필은 설치하지 않습니다. 자체 키 프로필의 키를 게임 기본값으로 복사하지 않습니다.
- XML을 해제하려면 `config.json`의 `actionmaps_path`를 빈 문자열로 저장하고 다시 실행하세요. 사용자 지정이 없는 버튼은 ESC 외 입력이 잠깁니다.

### 레이아웃 편집과 이전 버전

**덱 설정 파일 열기**는 exe 옆 `deck_layout.json`을 엽니다. 없으면 내장 기본값을 복사합니다. 저장 후 태블릿을 새로고침하세요.

v3 이하의 기존 파일은 지우거나 덮어쓰지 않고 보존하며 새 내장 v4 덱을 사용합니다. 직접 편집한 v4 파일은 내장 덱보다 우선합니다. 기존 v4 전력 페이지의 출력 배분 버튼도 자동으로 공통 최상단에 옮겨 표시하며 파일 자체는 수정하지 않습니다. `action`은 현재 XML 액션 식별자이며 `keys`에 임의 기본값을 써도 XML 확인이나 팝업의 명시적 사용자 지정 없이는 전송하지 않습니다. 지원 동작은 `tap`, `hold`입니다. 자동 시간 유지/매크로는 입력 API에서 허용하지 않습니다.

참고한 정보구조와 액션 자료:
- [tablet-deck](https://github.com/nodieCode/tablet-deck): 공통 바로가기, 작업별 묶음, Prospector의 채굴+함선 기능 배치
- [Boxxy-Binder AllBinds](https://github.com/BoxximusPrime/Boxxy-Binder/blob/55d681fde171be05a67a1def65265018fbbcde7b/AllBinds.xml): 액션 식별자 대조. 현재 패치의 게임 기본값/정책 승인 근거는 아닙니다.

## 안전장치와 제한

- 6자리 페어링 코드, IP별 5회 실패 시 1분 차단. 코드는 exe 옆 설정에 저장됩니다. 같은 Wi-Fi의 신뢰하는 기기에서만 사용하세요.
- 기본 설정은 `StarCitizen.exe`가 최전면인지 확인합니다. 확인 실패 시 차단합니다. 다른 창으로 바뀌면 홀드를 해제합니다.
- 홀드 무응답 5초 자동 해제, 탭 전환/페이지 숨김/연결 이탈 시 해제 요청, 종료 시 해제 시도
- Windows 표준 SendInput 사용. 게임이 관리자 권한이면 권한 차이 때문에 입력이 거부될 수 있습니다. 방화벽/권한을 무작정 해제하지 마세요.
- LAN HTTP 연결입니다. 인터넷 포트 포워딩 금지. 보안 경계가 필요한 공용/업무 네트워크에 노출하지 마세요.
- 비공식 팬 도구입니다. 이런 구현 방식이 이용약관/안티치트 허용을 보장하는 것은 아닙니다. 게임 정책을 확인하고 사용 여부는 직접 판단하세요.
- 실제 게임 플레이/안티치트 호환성, 패치별 키/광물 수치는 별도 인게임 검증이 필요합니다.

## 파일과 문제 확인

exe 옆에 `config.json`, `sc_pad_control.log`가 만들어집니다. 화면 영역과 설정은 유지됩니다. 개인 경로/페어링 코드가 든 설정·로그는 공개 저장소에 올리지 마세요.

접속 불가: PC 프로그램 실행 여부, 같은 개인 Wi-Fi, 제어 창 주소, Windows 방화벽의 개인 네트워크 허용을 확인합니다. 입력 불가: 게임 포커스, 현재 바인딩, 실행 권한을 확인합니다. 오버레이 테스트/결과 지우기는 게임 키를 보내지 않습니다.

## 개발/검증

```
pip install -r requirements.txt pyinstaller httpx
python -m unittest -v test_deck.py
```

웹 UI 검증은 개발 환경에서 `pip install playwright`, `playwright install chromium` 후 `python tests/frontend_smoke.py`로 실행할 수 있습니다.

GitHub Actions가 Windows에서 단일 exe를 만들고 실제 exe HTTP 스모크 테스트를 거친 뒤 Release에 올립니다. 회귀 테스트는 위 명령으로 별도 실행합니다. 빌드 옵션은 `.github/workflows/build.yml`이 기준입니다. 로컬 수동 빌드에도 `--noconsole`과 `deck_layout.json` 번들을 포함해야 합니다.
